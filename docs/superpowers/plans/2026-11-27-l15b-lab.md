# L15b Lab (Library Solve, Explicit Euler, RK4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the L15b lab, in which students write the PS6-style library solve, explicit Euler,
RK4, and a fixed-step loop on the L15a memory circuit. Students then measure how the error grows
with the step.

**Architecture:** Students complete four function bodies in `weeks/week-15/L15b/src/Compute.jl`
(module `L15bMethods`): `mysolve`, the two methods of `mystep`, and `myintegrate`. The reference
lives in `src/solution/Compute-solution.jl`, and the figures live in `src/Visualize.jl` (module
`L15bPlots`). The notebook builds the model with the course package (`build`, `steady_state`,
`set_input!`, `balances!`), and its check cells compare the students' functions with the package
`advance` and `integrate`. The week-15 suite tests the functions directly, then runs the notebook
with the solution swapped in.

**Tech Stack:** Julia 1.12, the course package `VLDataScienceMachineLearningPackage`, OrdinaryDiffEq
(`ODEProblem`, `Tsit5`), Plots, Test.

**Spec:** [docs/superpowers/specs/2026-11-27-l15b-lab-design.md](../specs/2026-11-27-l15b-lab-design.md).
It amends §6 of [the week-15 design](../specs/2026-11-25-week-15-ode-solvers-design.md). This plan
replaces Task 5 of [the slice-1 plan](2026-11-25-week-15-slice-1-explicit-methods.md) and covers the
L15b part of its Task 6.

## Review Focus

1. **A step above Euler's limit (Things to Try):** a student sets `Δt` above the memory circuit's Euler step limit, so the Euler run grows or turns nonfinite. The Task 2 and Task 3 check cells must still pass, because they compare only up to the last column where the package run is finite. The figures must still draw. (Test in Task 3.)
2. **Stops at or outside the ends of the run:** `mysolve` receives a stop equal to `t_start` or `t_final`, or one past `t_final`. It keeps only the stops strictly inside the span, and its result equals the run with only those stops. (Test in Task 1.)
3. **The library solve fails:** when the return code is not a success, `mysolve` stops with an `ErrorException` saying that the solver stopped early. It never returns a short run. (Test in Task 1.)
4. **Off-grid steps:** when `Δt` does not divide the span of `myintegrate`, or `Δt_save` does not divide the span of `mysolve`, the function throws an `ArgumentError`. Neither function silently shortens or stretches the run. (Tests in Tasks 1 and 2.)
5. **Edit, save, re-run:** a student fixes a TODO and re-runs the setup cell. The re-included `src/Compute.jl` replaces the module, and the qualified calls use the new code. (Test in Task 1.)

### Task 2: `mystep` (Euler and RK4) and `myintegrate`

**Files:**
- Modify: `weeks/week-15/L15b/src/solution/Compute-solution.jl` and `weeks/week-15/L15b/src/Compute.jl`
- Test: `instructor/validation/week-15/runtests.jl`

**Interfaces:**
- Consumes: the Task 1 module and imports. The package `advance(f!, x, p, t, Δt; algorithm)` and `integrate(f!, x₀, p; t_start, t_final, Δt, algorithm)` serve only as checks.
- Produces:
  - `mystep(algorithm::ExplicitEulerMethod, f!::Function, x::Vector{Float64}, p, t::Float64, Δt::Float64)::Vector{Float64}`
  - `mystep(algorithm::RungeKutta4Method, f!::Function, x::Vector{Float64}, p, t::Float64, Δt::Float64)::Vector{Float64}`
  - `myintegrate(f!::Function, x₀::Vector{Float64}, p; t_start::Float64, t_final::Float64, Δt::Float64, algorithm::AbstractFixedStepAlgorithm)::NamedTuple` returns `(t = t, x = x, evaluations = evaluations)`. Here `t[k] = t_start + (k − 1)Δt`, and `x` is `length(x₀) × (number of steps + 1)`.

**What students write:**
- **The Euler `mystep`:** the slope at the start of the step, and the update.
- **The RK4 `mystep`:** the four slopes, and the update with the weights 1, 2, 2, 1. The docstring of each method states the method and works one step on the test equation.
- **`myintegrate`:** allocate `t` and `x`, store `x₀` in column 1, and loop over the steps. Each pass computes the time from its index and calls `mystep(algorithm, ...)`, and Julia picks the method of `mystep` by the type of `algorithm`.

**Supplied in `myintegrate`:** the argument checks of the package `integrate`, as separate if-blocks, and the return line with `evaluations = number_of_steps * evaluations_per_step(algorithm)`.

- [ ] **Step 1: Write the failing tests** in `@meeting "L15b" begin @testset "L15b mystep and myintegrate" ... end end`. Add the answer markers `mystep(algorithm, ` (the call in the loop, not the signatures) and `f!(k₄` to the Task 1 list. `T` and `Δt` are test constants, and `decay!` is the suite's test equation.

```julia
for alg in (ExplicitEulerMethod(), RungeKutta4Method())
    @test_throws ErrorException starter.mystep(alg, balances!, x₀, model, 0.0, Δt)
    @test_throws ErrorException starter.myintegrate(balances!, x₀, model; t_start = 0.0, t_final = T, Δt = Δt, algorithm = alg)
    for (x, t) in states  # (x₀, 0.0); a state and its time inside the pulse, from integrate; a seeded random positive state at 0.0
        @test isapprox(sol.mystep(alg, balances!, x, model, t, Δt), advance(balances!, x, model, t, Δt; algorithm = alg); rtol = 1e-12)
    end
    for step in (Δt, Δt / 2)
        mine = sol.myintegrate(balances!, x₀, model; t_start = 0.0, t_final = T, Δt = step, algorithm = alg)
        pkg = integrate(balances!, x₀, model; t_start = 0.0, t_final = T, Δt = step, algorithm = alg)
        @test mine.t == pkg.t
        @test isapprox(mine.x, permutedims(pkg.x); rtol = 1e-12)
        @test mine.evaluations == pkg.evaluations
    end
    @test_throws ArgumentError sol.myintegrate(balances!, x₀, model; t_start = 0.0, t_final = T, Δt = T / (round(T / Δt) + 0.5), algorithm = alg)  # Review Focus 4
end

@test sol.mystep(RungeKutta4Method(), decay!, [1.0], λ, 0.0, Δt)[1] ≈ 1 + z + z^2/2 + z^3/6 + z^4/24
```
