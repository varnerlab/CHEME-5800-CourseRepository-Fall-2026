VLDataScienceMachineLearningPackage.MyBinaryWeightedMajorityAlgorithmModel — Type
mutable struct MyBinaryWeightedMajorityAlgorithmModel <: AbstractOnlineLearningModel

The binary weighted majority algorithm (WMA), the online learning method of week 10 (L10b).

In each round, n experts each predict an outcome of -1 or +1. The algorithm predicts the side with the larger total expert weight. Then the adversary reveals the actual outcome, and every expert that was wrong has its weight multiplied by 1 − ϵ. The function play(model, data) in Online.jl runs the T rounds.

Fields

  • ϵ::Float64: the learning rate: the fraction of weight a wrong expert loses in one round.
  • n::Int64: the number of experts.
  • T::Int64: the number of rounds.
  • weights::Array{Float64,2}: the expert weights, (T + 1) × n: row t holds the weights at the start of round t. build sets every entry to 1. play fills rows 2 to T + 1, and it changes this array in place.
  • expert::Function: the expert function, called as expert(i, t, data). It returns the prediction of expert i in round t, either -1 or +1.
  • adversary::Function: the adversary function, called as adversary(t, data). It returns the actual outcome of round t, either -1 or +1.

How to create one

Call build(MyBinaryWeightedMajorityAlgorithmModel, (ϵ = ..., n = ..., T = ..., expert = ..., adversary = ...)), defined in Factory.jl, where expert and adversary are functions we have written. All five keys are required; build creates weights itself.

VLDataScienceMachineLearningPackage.MyClassicalHopfieldNetworkModel — Type
mutable struct MyClassicalHopfieldNetworkModel <: AbstractlHopfieldNetworkModel

A classical Hopfield network: a network that stores a few patterns (memories) and recovers a stored pattern from a noisy copy. No course notebook uses this type.

Each memory is a vector of N entries, each -1 or +1, e.g., the pixels of a black-and-white image. The function recover(model, sₒ, trueenergyvalue) in Hopfield.jl starts from the state sₒ. It repeatedly picks one entry j at random and sets it to the sign of W[j,:]⋅s − b[j].

Fields

  • W::Array{<:Number, 2}: the weight matrix, N × N. build sets W = (1/N)⋅Σₖ mₖ⋅mₖᵀ, the sum over the memories mₖ, with zeros on the diagonal. build stores W as Float64 values; the bias b and the energies are Float32.
  • b::Array{<:Number, 1}: the bias vector, length N. build sets every entry to zero.
  • memories::Array{<:Number, 2}: the stored memories, N × K: one memory per column.
  • energy::Dict{Int64, Float32}: memory number k → the energy E(mₖ) = −(1/2)⋅mₖᵀ⋅W⋅mₖ − bᵀ⋅mₖ of that memory. A lower energy means a more stable state.

How to create one

Call build(MyClassicalHopfieldNetworkModel, (memories = ...,)), defined in Factory.jl, where the memories are an N × K matrix with one memory per column. build computes W, b, and energy.

VLDataScienceMachineLearningPackage.MyDirectedBipartiteGraphModel — Type
mutable struct MyDirectedBipartiteGraphModel <: AbstractGraphModel

A flow network: a directed graph with a source node, a sink node, and a capacity on each edge (week 5). build_flow_graph(...) in FlowValidation.jl builds one for L5a, and the L5b lab builds one for a worker–task assignment network. Then maximumflow(graph, source, sink) computes the largest flow that the network can carry from the source to the sink.

The name says bipartite, but build accepts any directed edge list. (In a bipartite graph, the nodes split into two groups, such as workers and tasks, and every edge joins the two groups.)

Fields

  • nodes::Union{Nothing, Dict{Int64, MyGraphNodeModel}}: node number → node. build numbers the nodes 1, 2, …, n.
  • edges::Union{Nothing, Dict{Tuple{Int, Int}, Number}}: edge (source, target) → the cost or weight of that edge.
  • children::Union{Nothing, Dict{Int64, Set{Int64}}}: node number → the set of its children, the nodes that one outgoing edge reaches.
  • edgesinverse::Dict{Int, Tuple{Int, Int}}: edge number → (source, target).
  • left::Set{Int64}: one node group of a bipartite graph. build does not set this field, so reading it gives an error.
  • right::Set{Int64}: the other node group. build does not set this field either.
  • source::Int64: the id of the source node, where the flow starts (the s key of build).
  • sink::Int64: the id of the sink node, where the flow ends (the t key of build).
  • capacity::Dict{Tuple{Int64, Int64}, Tuple{Number, Number}}: edge (source, target) → (lower, upper) bounds on its flow. build keeps the node ids from the edge file here, so those ids should be 1, 2, …, n. maximumflow uses only the upper bound.

How to create one

VLDataScienceMachineLearningPackage._rref! — Method
_rref!(A::Matrix{T}, ɛ = (default below)) where T -> Matrix{T}

Put the matrix A in reduced row echelon form, in place, by Gauss-Jordan elimination with partial pivoting, and return A. The ! at the end of the name is a Julia convention: the function changes its argument.

In reduced row echelon form, the first nonzero entry of each row (its pivot) is 1, each pivot is to the right of the pivot in the row above, and every other entry in a pivot's column is 0. We work column by column. In the current column, we find the entry of largest absolute value at or below the current row; choosing the largest entry (partial pivoting) keeps the rounding errors small. We swap that entry's row up to the current row, divide the row by the pivot so the pivot becomes 1, and subtract multiples of the row from every other row so the rest of the column becomes 0. When every candidate entry in a column is at most ɛ in absolute value, the column has no pivot: we set those entries to zero and move on to the next column.

Arguments

  • A::Matrix{T}: the matrix, with nr rows and nc columns, whose entries have the number type T. It is overwritten.
  • ɛ: the size below which an entry counts as zero. The default is 0 when T is a Rational or Integer type. Pass a Float64 or Rational matrix: the row operations divide, an Integer matrix cannot store the fractions, and the function stops with an InexactError. Otherwise it is eps(norm(A,Inf)): norm(A,Inf) is the largest absolute entry of A, and eps(x) is the gap between x and the next larger floating point number.

Returns

  • Matrix{T}: the same matrix A, now in reduced row echelon form.

_search(graph::T, start::MyGraphNodeModel, algorithm::BellmanFordAlgorithm)
    -> Tuple{Dict{Int64, Float64}, Dict{Int64, Union{Nothing, Int64}}} where T <: AbstractGraphModel

Compute the shortest distance from start to every node of graph with the Bellman-Ford algorithm, which allows negative edge weights. findshortestpath calls this method when algorithm is a BellmanFordAlgorithm().

The method follows the L4c pseudocode. After the "Initialize" step, we make at most |V| − 1 passes over the edges, where |V| is the number of nodes. Each pass does three steps:

  1. Reset the change flag: changed ← false.
  2. Relax every edge: for each edge u → v, compute alt = dist[u] + w(u,v). If alt < dist[v], set dist[v] = alt, prev[v] = u, and changed ← true.
  3. Check for convergence: if no distance changed in the pass, stop the passes.

Then we check for a negative-weight cycle: if any edge can still lower a distance, a cycle whose weights sum to a negative number is reachable from start, and no shortest path exists.

The L4c pseudocode skips an edge when dist[u] = ∞. This version does not skip it, but such an edge changes nothing, because alt = ∞ + w(u,v) = ∞ is never smaller than dist[v]. We visit the edges in the order the graph.edges dictionary gives them. That order can change how many passes we need, and which route we keep when two routes tie, but not the distances.

_solve(model::MyBinaryVectorArmsEpsilonGreedyAlgorithmModel, context::MyConsumerChoiceBanditContextModel;
    T::Int = 0, world::Function = _null, startdayindex::Int = 1) -> Tuple

Play T rounds of the consumer-choice bandit with an epsilon-greedy rule. Each arm is a bundle of K goods: a vector of K zeros and ones, where a 1 means the bundle includes that good. No notebook in this course calls this method.

Arms and bundles. There are N = 2^K arms. Arm i uses the binary digits of i, least significant digit first, padded with zeros to K digits; Julia's digits(i, base=2, pad=K) makes this vector. The binary digits of N itself need K+1 digits, so arm N uses the digits of N − 1 instead. As a result, arms N − 1 and N both choose every good, and no arm chooses the empty bundle.

The world. The call world(startdayindex, aₜ, context) returns four values (r, n, p, γ): the reward r of the bundle aₜ, and three vectors of length K that we store without using. Every call passes the same startdayindex.

The method.

  1. Initialize: for each arm i = 1, 2, …, N, call the world once with the bundle of arm i. Set the estimated reward μ[i] = (1 − 1/T)⋅μₒ[i] + (1/T)⋅r, a blend of the starting estimate μₒ[i] from the context and the observed reward r.
  2. For each round t = 2, 3, …, T: compute ϵₜ = (log(K⋅t) / t)^(1/3), which is not capped at 1. Draw a uniform random number u between 0 and 1. If u ≤ ϵₜ, choose the arm î uniformly at random from 1, 2, …, N. Otherwise, choose the arm with the largest μ, the first one on a tie. Call the world with the bundle of arm î and receive the reward rₜ. Move μ[î] a fraction 1/t of the way toward the reward: μ[î] ← μ[î] + (1/t)⋅(rₜ − μ[î]).

Random draws, in order: the N world calls of step 1; then, in each round, rand() for u, rand(1:N) only when exploring, and the world call. Both rand calls use Julia's default random number generator.

  • context::MyConsumerChoiceBanditContextModel: the problem data. We use context.μₒ, the starting estimate of the reward of each of the N arms, and pass context on to world.
  • T::Int = 0: the number of rounds. It must be at least 1: with T = 0, the first store into the reward history fails with a BoundsError.
  • world::Function = _null: the function world(startdayindex, aₜ, context) described above. The default _null takes one argument, so it fails with a MethodError; always pass world.
  • startdayindex::Int = 1: the day index passed to world in every call.

Returns

  • R::Array{Float64,2}: the T × N reward history. Row 1 holds the reward of every arm from step 1. Row t ≥ 2 holds the reward of round t in the column of the arm chosen, and zeros elsewhere.

VLDataScienceMachineLearningPackage._solve — Method
_solve(model::MyEpsilonGreedyAlgorithmModel; T::Int = 0, world::Function = _null,
    return_history::Bool = false) -> Union{Array{Float64,2}, NamedTuple}

Play T rounds of a K-arm bandit with the epsilon-greedy algorithm.

The algorithm first pulls each arm once: arm a in round a, for a = 1, 2, …, K. Then, in each round t = K+1, K+2, …, T, it takes four steps:

  1. Compute the exploration probability ϵₜ = min(1, (K⋅log t / t)^(1/3)), where log is the natural logarithm.
  2. Draw a uniform random number u between 0 and 1. If u ≤ ϵₜ, explore: choose an arm uniformly at random from 1, 2, …, K, which can be the current best arm. Otherwise, exploit: choose the arm with the largest sample mean reward μ̄(a). A tie goes to the arm with the smallest index.
  3. Pull the chosen arm aₜ and receive the reward rₜ.
  4. Add rₜ to the total reward of arm aₜ and add 1 to its pull count Nₐ. The sample mean μ̄(a) is the total reward of arm a divided by Nₐ.

The algorithm has two phases. In the exploration phase, it pulls each arm N times: arm 1 in the first N rounds, then arm 2 in the next N rounds, and so on. The number of pulls per arm is N = (T/K)^(2/3)⋅(log T)^(1/3), where log is the natural logarithm. We round N to the nearest integer (a value exactly halfway rounds to the even integer). Compute shortest-path distances from source, allowing negative edge weights. Return distances and previous, keyed by vertex identifier; unreachable vertices retain Inf and nothing. The edge vector must be nonempty and contain the source. A reachable negative-weight cycle raises ArgumentError instead of returning a result.

The method follows the L4c pseudocode. We make at most |V| − 1 passes over the edges, where |V| is the number of vertices. Each pass does three steps:

  1. Reset the change flag: changed ← false.
  2. Relax every edge: for each edge u → v with dist[u] < ∞, compute alt = dist[u] + w(u,v). If alt < dist[v], set dist[v] = alt, prev[v] = u, and changed ← true.

A shortest route without a cycle uses at most |V| − 1 edges, so |V| − 1 passes are enough. We then check for a negative-weight cycle: we visit every edge once more, and if an edge can still lower a distance, a cycle with negative total weight is reachable from the source, and no shortest path exists.

Build a flow network: a directed graph with a source node, where flow enters, a sink node, where flow leaves, and capacity bounds on every edge. The maximumflow(...) method in Graphs.jl and validate_flow(...) in FlowValidation.jl read this model. build_flow_graph(...) in FlowValidation.jl calls this method.

The method builds the graph part in the same five steps as the graph build(...) method above: it renumbers the nodes 1, 2, …, n in sorted order of their ids, stores each edge weight under (source, target), numbers the edges, and finds the children of each node. Then it adds:

  • the capacity of each edge, the pair (lower, upper), stored under (source, target);
  • the source and sink node ids, stored as given.

The capacity dictionary and the source and sink use the original node ids from the edge models. The nodes, edges, edgesinverse, and children fields use the new numbers. The two agree when the node ids are already 1, 2, …, n, as in the week 5 edge files. maximumflow(...) reads the capacity keys as row and column numbers of an n × n matrix, so it needs ids 1, 2, …, n.

The method does not set the fields left and right. Reading either field stops with an UndefRefError.

Arguments

  • modeltype::Type{MyDirectedBipartiteGraphModel}: the model type to build.
  • data::NamedTuple: the network data. It must have the keys:
    • s::Int64: the id of the source node.
    • t::Int64: the id of the sink node.
    • edges::Dict{Int, MyConstrainedGraphEdgeModel}: the edges, keyed by edge id. The course reads them from a file with MyConstrainedGraphEdgeModels(...).

Returns

  • MyDirectedBipartiteGraphModel: the network, with the fields
    • nodes::Dict{Int64, MyGraphNodeModel}: node number => node model.
    • edges::Dict{Tuple{Int64, Int64}, Number}: (source, target) => edge weight.
    • edgesinverse::Dict{Int, Tuple{Int, Int}}: edge number => (source, target).
    • children::Dict{Int64, Set{Int64}}: node number => the set of its children.
    • capacity::Dict{Tuple{Int64, Int64}, Tuple{Number, Number}}: (source, target) => (lower, upper).
    • source::Int64 and sink::Int64: the source and sink node ids.

Throws

  • a MethodError, if an edge has nothing as its weight, its lower bound, or its upper bound, because the edges and capacity dictionaries hold only numbers.
  • an error, if data lacks one of the three keys.

Example

edges = Dict{Int, MyConstrainedGraphEdgeModel}();
edges[1] = build(MyConstrainedGraphEdgeModel, (id = 1, source = 1, target = 2, weight = 0.0, lower = 0.0, upper = 5.0));
edges[2] = build(MyConstrainedGraphEdgeModel, (id = 2, source = 2, target = 3, weight = 0.0, lower = 0.0, upper = 3.0));
network = build(MyDirectedBipartiteGraphModel, (s = 1, t = 3, edges = edges));
network.capacity[(2, 3)]   # (0.0, 3.0)

An MDP describes an agent that is in a state s, takes an action a, collects the reward R(s, a), and moves to the next state s′ with probability T(s′ | s, a). The discount factor γ is the weight of a reward one step in the future, relative to the same reward now.

Every key is optional. A missing key gets a placeholder:

  • 𝒮 and 𝒜: a vector with one entry whose value is not set;
  • T: a 1×1×1 array whose value is not set;

  • γ: the value 0.1.

A value that is not set holds whatever bits were in memory, so it means nothing. We pass every key when we build a model that we plan to solve.

    • 𝒜::Array{Int64,1}: the actions, numbered 1, 2, …, |𝒜|.
    • T::Array{Float64,3}: the transition probabilities. The entry T[s, s′, a] is the probability of moving from state s to state s′ when we take action a. The field also accepts a function, but the package's MDP methods read T as an array.
    • R::Array{Float64,2}: the rewards. The entry R[s, a] is the reward for taking action a in state s. The field also accepts a function, but the package's MDP methods read R as an array.

  • data::NamedTuple: the model data. It must have the keys:
    • ϵ::Float64: the learning rate of the multiplicative weights update.
    • n::Int: the number of actions of the row player (the experts).

Build a graph, such as a MySimpleDirectedGraphModel, from a dictionary of edge models. The course reads the edge models from a file with MyGraphEdgeModels(...) in Files.jl, and passes them here. Unlike the other methods in this file, the second argument is a dictionary, not a NamedTuple.

The method works in five steps:

  1. It collects the id of every node that appears as the source or the target of an edge, and sorts the ids in increasing order.
  2. It renumbers the nodes 1, 2, …, n in that order. For example, the nodes 10, 20, 30 become 1, 2, 3. Every field of the graph uses the new numbers.

  5. It stores the children of each node: the set of nodes that the edges leaving the node point to.

  • edgemodels::Dict{Int64, MyGraphEdgeModel}: the edges, keyed by edge id. Each edge model gives a source node id, a target node id, and a numeric weight.

  • T: the graph, with the fields
    • nodes::Dict{Int64, MyGraphNodeModel}: node number => node model. Each node carries no data (nothing).
    • edges::Dict{Tuple{Int64, Int64}, Number}: (source, target) => edge weight.
    • edgesinverse::Dict{Int, Tuple{Int, Int}}: edge number => (source, target).
    • children::Dict{Int64, Set{Int64}}: node number => the set of its children. A node with no outgoing edge has an empty set.

VLDataScienceMachineLearningPackage.dijkstra — Method
dijkstra(edges::AbstractVector{WeightedEdge}, source::Integer) -> NamedTuple

Compute shortest-path distances from source when every edge weight is nonnegative. The result contains distances (minimum costs) and previous (chosen predecessors), both keyed by vertex identifier. Unreachable vertices retain Inf and nothing. The source has distance zero and no predecessor. The edge vector must be nonempty and contain the source among its endpoints.

The method follows the L4c pseudocode. A min-priority queue Q holds the discovered vertices that wait to be processed, each with its distance estimate as its priority. Each pass of the main loop does three steps:

  1. Select a vertex: remove the vertex u with the smallest estimate from Q.
  2. Mark it as processed: skip u if it is already in the processed set S; otherwise add it.
  3. Relax its outgoing edges: for each edge u → v, compute alt = dist[u] + w(u,v). If alt < dist[v], set dist[v] = alt and prev[v] = u, and give v priority alt in Q.

When every weight is nonnegative, no later route can be cheaper than the estimate of the vertex we select, so that estimate is final.

Arguments

  • edges::AbstractVector{WeightedEdge}: the edges of the graph; at least one edge, and every weight ≥ 0.
  • source::Integer: the source vertex s. It must be an endpoint of some edge.

Returns

A NamedTuple with the fields:

  • distances::Dict{Int64, Float64}: key v holds the shortest distance from s to v; Inf when v is unreachable.
  • previous::Dict{Int64, Union{Nothing, Int64}}: key v holds the vertex before v on the selected shortest route; nothing for the source and for unreachable vertices.

Throws

  • ArgumentError: an edge weight is negative, edges is empty, source is a Bool, or source is not a vertex of the graph.

In each round t = 1, 2, …, T:

  1. Ask each expert i = 1, 2, …, n for its prediction, expert(i, t, data): 1 (up), -1 (down), or 0 (no prediction).

VLDataScienceMachineLearningPackage.qriteration — Method
qriteration(A::Array{Float64,2}; maxiter::Int64 = 10,
    tolerance::Float64 = 1e-9) -> Tuple{Array{Float64,1}, Dict{Int64,Array{Float64,1}}}

Estimate the eigenvalues and eigenvectors of a real square matrix A with the QR iteration method.

Phase 1 estimates the eigenvalues. Each iteration factors the current matrix as A_k = Q⋅R, where Q is orthogonal (its columns are perpendicular unit vectors, so Qᵀ⋅Q = I) and R is upper triangular. It then forms A_{k+1} = Qᵀ⋅A_k⋅Q, which equals R⋅Q and has the same eigenvalues as A_k. When the eigenvalues of A are real and have different absolute values, A_k approaches an upper triangular matrix, and its diagonal approaches the eigenvalues. We stop when the diagonal changes by less than tolerance (measured by the Euclidean norm of the change) between two iterations, or after maxiter iterations, whichever comes first. The function does not report which of the two happened.

Phase 2 estimates one eigenvector for each eigenvalue estimate λᵢ. We row-reduce the augmented matrix [A − λᵢI b], where I is the identity matrix and b is zero except for its last entry. That entry is the last diagonal entry of the upper triangular form of A − λᵢI, or 1 when that entry is exactly zero. We take the last column x of the reduced matrix and divide it by its length. When the row reduction finds a pivot in every column of A − λᵢI, the reduced matrix is [I x], so x solves (A − λᵢI)⋅x = b. This is one step of the inverse iteration method. When λᵢ is close to an eigenvalue, the step usually turns x toward that eigenvalue's eigenvector. It does not always do so, because the result also depends on the right-hand side b. For A = [2.0 1 0; 1 3 0; 0 0 10], the first two vectors returned are eigenvectors of the eigenvalue 10. The function does not check its vectors. Before you use a returned vector x, compare A⋅x with λᵢ⋅x. Last, we multiply the eigenvector by (−1)^(i+1), which flips the sign of every second eigenvector. An eigenvector times −1 is still an eigenvector; the code does not record why it flips these signs.

Arguments

  • A::Array{Float64,2}: a real square matrix of size n × n. It is not changed.
  • maxiter::Int64 = 10: the most QR iterations in phase 1.
  • tolerance::Float64 = 1e-9: phase 1 stops when the norm of the change in the diagonal is less than this value.

Returns

A tuple (λ, eigenvectors):

  • λ::Array{Float64,1}: the eigenvalue estimates, sorted from smallest to largest.
  • eigenvectors::Dict{Int64,Array{Float64,1}}: eigenvectors[i] is a unit-length eigenvector estimate for λ[i]. When the row reduction treats A − λᵢI as singular, the last column of the reduced matrix can come out all zeros, and eigenvectors[i] is then all NaN ("not a number").

Each call to world(a) should draw one reward of arm a, independently, from the arm's fixed reward distribution, with rewards between 0 and 1. The algorithms see only these rewards. Every sample mean includes the rewards that are exactly zero, and every tie goes to the arm with the smallest index.

The three algorithms:

  • Explore-first pulls each arm N times, where N = (T/K)^(2/3)⋅(log T)^(1/3) rounded to the nearest integer and kept between 1 and ⌊T/K⌋. Then it pulls the arm with the largest sample mean for the rest of the game.

VLDataScienceMachineLearningPackage.solve — Method
solve(A::AbstractMatrix{T}, b::AbstractVector{T}, xₒ::AbstractVector{T};
    algorithm::AbstractLinearSolverAlgorithm = JacobiMethod(), ϵ::Float64 = 1e-6,
    maxiterations::Int64 = 1000, ω::Float64 = 1.0) where T <: Number -> Dict{Int,Array{Float64,1}}

Solve the linear system A⋅x = b with an iterative method, and return every iterate.

Each method starts from the initial guess x⁽⁰⁾ = xₒ and repeats a residual correction. At iteration k, we compute the residual r⁽ᵏ⁾ = b − A⋅x⁽ᵏ⁾, solve M⋅d⁽ᵏ⁾ = r⁽ᵏ⁾ for the correction d⁽ᵏ⁾, and set x⁽ᵏ⁺¹⁾ = x⁽ᵏ⁾ + d⁽ᵏ⁾. We write A = D + L + U, where D holds the diagonal entries of A, L the entries below the diagonal, and U the entries above it. The algorithm argument chooses the matrix M:

  • JacobiMethod(): M = D;
  • GaussSeidelMethod(): M = D + L;
  • SuccessiveOverRelaxationMethod(): M = D/ω + L, with relaxation factor ω.

We check the residual before the correction limit. So an initial guess with ‖r⁽⁰⁾‖₂ < ϵ takes zero corrections, and an iterate that meets the tolerance after the last allowed correction counts as converged. When we reach the correction limit, or the residual norm grows above 10¹⁰, we print a warning and return the iterates so far. Check the residual of the last iterate to tell convergence apart from a warning return.

Arguments

  • A::AbstractMatrix{T}: the n × n system matrix. Every diagonal entry must be nonzero.
  • b::AbstractVector{T}: the right-hand side, a vector of length n.
  • xₒ::AbstractVector{T}: the initial guess x⁽⁰⁾, a vector of length n.
  • algorithm::AbstractLinearSolverAlgorithm = JacobiMethod(): the method: JacobiMethod(), GaussSeidelMethod(), or SuccessiveOverRelaxationMethod().
  • ϵ::Float64 = 1e-6: the residual tolerance: we stop when ‖r⁽ᵏ⁾‖₂ < ϵ.
  • maxiterations::Int64 = 1000: the correction limit, the most corrections we make. It must be zero or larger.
  • ω::Float64 = 1.0: the relaxation factor. Only SuccessiveOverRelaxationMethod() uses it.

where T <: Number means that T stands for one number type, such as Float64, and that A, b, and xₒ must all have that same element type. For example, an integer matrix A with a Float64 vector b matches no method, and Julia stops with a MethodError.

Returns

  • Dict{Int,Array{Float64,1}}: the archive of iterates. Key 0 holds the initial guess, and key k holds the iterate after k corrections. The largest key is the number of corrections made, and it is never larger than maxiterations. The archive holds one more entry than the number of corrections.

Throws

  • an ArgumentError if maxiterations is negative.
  • an ErrorException if a diagonal entry of A is zero.

Example

VLDataScienceMachineLearningPackage.walk — Method
walk(graph::T, startnode::MyGraphNodeModel; algorithm::AbstractGraphTraversalAlgorithm = BreadthFirstSearchAlgorithm(),
    verbose::Bool = false) -> Array{Int64,1} where T <: AbstractGraphModel

The walk function traverses the graph starting from a given node using the specified algorithm (either Depth-First Search or Breadth-First Search). It maintains a set of visited nodes to avoid cycles and ensure that each node is processed only once.

Depth-first search (_DFS) follows one branch as far as it can before it returns to try the next branch. Breadth-first search (_BFS) visits the nodes in layers: the start node, then every node one edge away, then every node two edges away, and so on. Both searches read the children of each node from a Set, which has no fixed order, so the order among the children of one node is not necessarily increasing.

Arguments

  • graph::T: The graph to traverse, where T is any subtype of AbstractGraphModel.
  • startnode::MyGraphNodeModel: The node to start the traversal from.
  • algorithm::AbstractGraphTraversalAlgorithm = BreadthFirstSearchAlgorithm(): The algorithm to use for the traversal, a keyword argument. Pass DepthFirstSearchAlgorithm() or BreadthFirstSearchAlgorithm().
  • verbose::Bool = false: Whether to print each visited node while the search runs (keyword argument).

Returns

  • Array{Int64,1}: The collection of visited node IDs in the order they were visited. Only the nodes reachable from startnode appear.

Throws

  • ErrorException: algorithm is neither a DepthFirstSearchAlgorithm nor a BreadthFirstSearchAlgorithm.

VLDataScienceMachineLearningPackage.∇f — Method
∇f(f, x, y, T, λ, θ, h) -> Array{Float64}

Estimate the gradient of the loss f(x, y, T, λ, θ) with respect to the parameters θ by forward finite differences. The logistic regression _learn(...) method calls this function once for each training example.

For each parameter θᵢ, we nudge it by a small step h and measure how much the loss changes:

∂f/∂θᵢ ≈ (f(x, y, T, λ, θ + h⋅eᵢ) − f(x, y, T, λ, θ)) / h,

where eᵢ is the vector with a 1 in entry i and zeros elsewhere. The loop evaluates f twice for each parameter: once at the nudged parameters and once at θ.

Arguments

  • f: the loss function, called as f(x, y, T, λ, θ). The logistic regression model stores it in its field L.
  • x: the feature vector of one training example.
  • y: the label of the example, -1 or 1.
  • T: passed on to f unchanged; the logistic regression model calls it the inverse temperature.
  • λ: passed on to f unchanged; the logistic regression model calls it the regularization parameter.
  • θ: the parameter vector at which we estimate the gradient. It is not changed.
  • h: the finite-difference step size.

Returns

  • Array{Float64}: the estimated gradient, with the same shape as θ.
